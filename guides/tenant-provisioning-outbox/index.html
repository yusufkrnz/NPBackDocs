Tenant Provisioning — Outbox Pattern

:::info Implementasyon durumu — 2026-08-14 Bu sayfadaki outbox motoru (session factory, tenant_outbox_events, poller, handler registry) kodlandı, gerçek Postgres'e karşı migration uygulandı ve smoke test'ten geçti. routers/admin.py (POST /admin/tenants) ve Auth Service (JWT decode) henüz kodlanmadı — bu ikisi olmadan akış uçtan uca çalışmaz, ama outbox motorunun kendisi bağımsız olarak hazır ve doğrulanmış durumda. Detaylı tablo: Implementasyon Durumu. :::

Platform Admin Service daha önce "tek fonksiyon, try/except, ayrı bir Saga'ya gerek yok" diyordu. SuperAdmin'in hangi adımın (Postgres/Mongo/mail) nerede takıldığını ayrı ayrı görebilmesi ve retry'nin otomatik olması ihtiyacı netleşince bu sayfadaki outbox pattern'e geçildi ve kodlandı.

Şema: tenant_outbox_events​

tenant_outbox_events
  id               uuid pk, default gen_random_uuid()
  tenant_id        uuid, FK -> tenants.id (ON DELETE CASCADE)
  event_type       varchar(50)   -- OutboxEventType: send_invite_email | seed_mongo_audit
  status           varchar(20)   -- OutboxStatus: pending / processing / succeeded / failed
  payload          jsonb
  attempt_count    int, default 0
  next_attempt_at  timestamptz, default now()
  last_error       text
  created_at       timestamptz
  updated_at       timestamptz

  index (status, next_attempt_at)  -- poller'ın claim sorgusu tam bunu kullanır

event_type/status kasıtlı olarak native Postgres ENUM değil, VARCHAR (SQLAlchemy Enum(..., native_enum=False)) — yeni bir event_type eklemek ALTER TYPE migration'ı gerektirmesin diye; uygulama seviyesinde Python enum yeterli.

Session Factory — core/db.py​

get_current_tenant_id (core/auth.py) şu an bilerek NotImplementedError atıyor — JWT decode Auth Service ile gelecek, o güne kadar get_tenant_session'a bağımlı hiçbir router yazılamaz. get_db_session bundan etkilenmez, Platform Admin router'ları bugünden yazılabilir.

Outbox Engine — dört ayrı sorumluluk​

İlk tasarımdaki tek-fonksiyon örneğinin aksine gerçek kod dört katmana ayrıldı — her biri tek başına test edilebilir:

DosyaSorumluluk
core/outbox/enums.pyOutboxEventType, OutboxStatus — tek kaynak, model/repository/handler hepsi buradan okur
core/outbox/backoff.pycompute_backoff(attempt_count) — saf fonksiyon, DB/asyncio bağımlılığı yok
core/outbox/handlers.pyProtocol + register_handler/get_handler registry — yeni event_type eklemek burada yeni bir dekoratör, poller/service/repository değişmez (Open/Closed)
core/outbox/repository.pyOutboxRepository — tabloya dokunan TEK yer (persistence, SRP)
core/outbox/service.pyOutboxService — orkestrasyon: claim → handler çağır → sonucu yaz. Repository'ye ve handler registry'ye soyutlama üzerinden bağımlı (DIP)
core/outbox/poller.pyOutboxPoller — asyncio görev döngüsü, stop() ile temiz kapanış

  • tests/test_outbox_backoff.py — compute_backoff saf fonksiyonu (3 test)
  • tests/test_outbox_handlers_registry.py — registry kayıt/lookup, kayıtsız event_type'ta HandlerNotRegisteredError (2 test)

    • Hata yolu: attempt_count artıyor, backoff next_attempt_at'i doğru öteliyor (bir sonraki turda erken claim edilmiyor), max_attempts'e ulaşınca failed (dead-letter)

SuperAdmin'de görünüm — henüz yok​

GET /admin/tenants/{id}/provisioning ve POST /admin/tenants/{id}/provisioning/{event_type}/retry (bkz. Platform Admin Service) henüz kodlanmadı — outbox motoru hazır olduğu için bu endpoint'ler OutboxRepository/tenant_outbox_events üzerine ince bir router katmanı olmaktan öteye gitmeyecek.

Idempotency notu​

At-least-once garanti (exactly-once değil). Mail gönderilip DB'ye succeeded yazılmadan poller çökerse mail 2. kez gidebilir — kabul edilen risk. seed_mongo_audit_handler zaten $setOnInsert + upsert ile idempotent yazıyor.

Sırada ne var​

  1. models/user.py, models/invitation.py
  2. routers/admin.py — POST /admin/tenants (tenant + admin user tek transaction'da, outbox event'leri aynı transaction'a insert)
  3. routers/admin.py — provisioning durumu + manuel retry endpoint'leri
  4. Auth Service — core/auth.py::get_current_tenant_id'yi JWT decode ile doldurmak
  5. Mongo bağlantısının gerçek ortamda (Docker/mevcut Mongo) doğrulanması — seed_mongo_audit_handler henüz canlı test edilmedi
