Token Design

Access token süresi dolunca client bu endpoint'i çağırır. Dönen refresh_token eskisinden farklıdır — her çağrıda rotasyon uygulanır (bkz. Rotasyon ve iptal).

Access token üretimi​

services/token_service.py
1import jwt
2from datetime import datetime, timedelta, timezone
3
4from core.settings import get_settings
5
6settings = get_settings()
7
8
9def create_access_token(user_id: str) -> str:
10 now = datetime.now(timezone.utc)
11 payload = {
12 "sub": user_id,
13 "iat": now,
14 "exp": now + timedelta(minutes=settings.access_token_expire_minutes),
15 }
16 return jwt.encode(payload, settings.jwt_secret, algorithm=settings.jwt_algorithm)

sub dışında (email, rol gibi) hiçbir kullanıcı bilgisi token'a gömülmez — rol her istekte DB'den taze okunur.

Refresh token üretimi​

services/token_service.py
1import hashlib
2import secrets
3from datetime import datetime, timedelta, timezone
4
5REFRESH_TOKEN_TTL_DAYS = 30
6
7
8def create_refresh_token() -> tuple[str, str]:
9 # (client'a dönülecek ham token, DB'ye yazılacak hash)
10 raw_token = secrets.token_urlsafe(48)
11 token_hash = hashlib.sha256(raw_token.encode()).hexdigest()
12 return raw_token, token_hash
13
14
15async def issue_refresh_token(db, user_id: str) -> str:
16 raw_token, token_hash = create_refresh_token()
17 await db.execute(
18 insert(RefreshTokens).values(
19 user_id=user_id,
20 token_hash=token_hash,
21 expires_at=datetime.now(timezone.utc) + timedelta(days=REFRESH_TOKEN_TTL_DAYS),
22 is_revoked=False,
23 )
24 )
25 return raw_token

Ham token DB'ye asla yazılmaz, sadece hash'i — şifrelerle aynı gerekçe. Doğrulama gelen token'ın hash'ini alıp karşılaştırır:

services/token_service.py
1async def verify_refresh_token(db, raw_token: str):
2 token_hash = hashlib.sha256(raw_token.encode()).hexdigest()
3 record = await db.scalar(select(RefreshTokens).where(RefreshTokens.token_hash == token_hash))
4 if record is None or record.is_revoked or record.expires_at < datetime.now(timezone.utc):
5 raise AuthenticationError(code="auth.refresh_token_invalid")
6 return record

Rotasyon ve iptal​

  • Logout → is_revoked = true
  • /auth/refresh → eski token is_revoked = true, yeni token üretilip döner (aynı token iki kez kullanılamaz; ikinci kullanım denemesi zaten iptal edilmiş bir token'a denk gelir — çalıntı token bu şekilde görünür hale gelir)
  • Access token iptal edilemez, bu yüzden ömrü kısa tutulur

Notlar​

  • jwt_secret .env'den okunur (bkz. coding-standards)
  • İmza simetrik (HS256) — token'ı tek bir servis (Auth Service) doğruladığı sürece yeterli
  • Refresh token httpOnly cookie'de tutulur, localStorage'da değil
  • Hata mesajları burada da code üzerinden döner, hardcoded metin değil (bkz. i18n notu)
